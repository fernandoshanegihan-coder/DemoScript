DemoScript, from recording to spoken demo.

A recording and a creator brief become a descriptive script. The presenter can rehearse, record or generate scene voices, then download one video with narration included.

Code snapshot: 5668640. This map is a reference, not a record of an interactive code tour. It can drift when the code changes.

The main pieces

  • The page and local work

    app/page.tsx owns the clip, context, script, modes and takes. sessionStore.ts saves the current project in IndexedDB. Sample preview bypasses that saved project.

  • Understanding and writing

    The video route analyzes footage with Gemini. The story route handles follow-ups and text-only writing. Scene timings and word budgets keep explanations with the footage.

  • Scene voices

    VoiceRecordingMode records the microphone. AutomaticNarration requests Azure speech through the server. Each take retains its script text so later edits can be detected.

  • The finished artifact

    narration.ts aligns the audio. videoExport.ts combines picture and sound in the browser using Mediabunny. The original source audio is replaced.

  1. 1. Entry and visible result

    components/NarrationExport.tsx — search async function build. The button starts alignment, reports progress and offers a preview/download only after success. Changing the clip, scenes or takes invalidates the prior result.

  2. 2. Preserve the scene timeline

    lib/narration.ts — search buildNarration and mixTimeline. Every spoken scene needs a current take. Samples start at absolute timestamps; deleted gaps stay silent. Overflow and overlap are refused rather than cropped.

  3. 3. Check what the user receives

    lib/videoExport.ts — search combineVideoAndNarration. Picture and narration are converted together, then the finished file is reopened to require both tracks. MP4/AVC/AAC is preferred when supported; WebM is the fallback.

A practice to reuse

Turn a user-visible failure into an artifact check. A silent downloaded video exposed a gap between a working preview and a usable output. The implementation now requires both media tracks and verifies audio timing instead of treating a successful button click as enough.

Evidence: narration.test.mjs checks empty media, stale takes, timing, overlap and overflow. video-export-check.html additionally decodes synthetic audio at expected intervals and checks silent gaps.

On another agent-assisted project, describe the observable result first, ask the agent to exercise the delivered artifact, and use the failure to choose a focused check. Track presence alone still does not establish natural narration, factual accuracy or every-browser compatibility.

Run and reopen

Use Node 24+. Install dependencies, copy .env.example to the ignored .env.local file and supply your own server credentials. Never put keys in client code or commit them.

npm install
npm run dev
# Open http://localhost:3000

npm test
npx tsc --noEmit

# Production preview on port 3001:
npm run build -- --webpack
npm run start -- --port 3001

Open this file directly from the project folder to use it offline. No scripts, external fonts or network services are needed to read the map. The app itself needs provider access for new analysis or generated narration; the prepared sample loads bundled media.
